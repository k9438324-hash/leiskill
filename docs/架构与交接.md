# 架构与交接

## 真源

- VERSION：整个仓库版本；四个技能 metadata.version 必须一致。
- catalog.json：正式技能名称、中文名、输入、输出与边界；独立安装的 lei 带同版本快照。
- skills/<name>/SKILL.md：该技能的具体流程与停止条件，正文优先于摘要。
- skills/<name>/agents/openai.yaml：中文界面名称、用途与调用提示。
- AGENTS.md：维护规则；CLAUDE.md 仅指向它。
- tools/validate.py：检查目录、版本、交接字段、界面元数据、内部链接和公开文件边界。

## 分工

lei 负责根据现有材料选择下一步；jj 负责审阅交接与剪辑执行；lei-doctor 只做环境诊断；lei-update 只在明确请求时更新。审稿为 jj 内部阶段，由本仓库原创流程及标准库脚本提供，不加载外部审稿 Skill。

叶子技能只描述自己的输入、输出、停止条件及工具依赖，不自行安排长串后续技能。更新、系统安装和素材读取权限各自沿用用户请求，不因进入路由扩大。

## 状态与证据

一视频、一聊天、一项目目录、一份 project-state.json。项目缓存与阶段 manifest 留在用户指定工作目录，仓库只分发技能和工具。确认记录、预计时长、素材引用、结构验证和播放导出各自保留来源。

## 扩展原则

只有可独立调用、已有真实流程与验证依据的能力才增加 Skill。不能为了凑数量，把 workbench 的每个子命令拆成空壳技能。新能力同时登记 catalog、入口快照、界面、文档与检查。
