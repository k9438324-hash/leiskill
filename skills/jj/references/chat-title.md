# 聊天改名

本步骤修改当前 Codex 左侧聊天标题。本地工作台目录、剪映原工程和已生成草稿各自保持现有名称。

## 执行

1. 读取当前项目 `qa/build.json`，确认 `ok=true` 且 `validation.ok=true`。以 `draft` 路径末级名称为目标标题；不得根据口头计划推测名称。
2. 查找 `set_thread_title`，包括环境提供的工具发现入口。只操作能可靠定位的当前聊天；调用成功后检查返回的标题，或读取当前聊天验证。已是目标标题时直接记录已匹配。
3. 无可调用的改名工具、调用失败或无法验证时，读取并使用当前环境提供的桌面控制 Skill。先确认当前 Codex 窗口及聊天，通过侧栏菜单的重命名入口修改标题，再读取界面或截图确认。已经授权的当前聊天改名无需重复询问。
4. 桌面控制运行时不可用、当前聊天无法可靠定位或界面操作失败时，保留草稿，记录具体阻塞原因和目标标题。最终明确说明“草稿已完成；聊天名未改”，给出用户可手动使用的准确名称。不要将改名尝试称为改名成功。

只通过受支持的聊天工具或可见界面操作；不通过修改 Codex 数据库、会话原始记录或内部接口模拟改名。

## 留档与续接

在当前项目写入 `qa/chat-title.json`：

```json
{
  "expected_title": "来自实际草稿文件夹名",
  "status": "renamed|already_matched|blocked",
  "method": "thread_tool|desktop_ui|none",
  "observed_title": null,
  "verified": false,
  "reason": "具体结果或阻塞原因",
  "checked_at": "ISO时间"
}
```

成功状态必须同时有 `verified=true` 且 `observed_title=expected_title`；改名请求仅被接受而未获得匹配证据时，仍记为 `blocked`。留档不包含聊天正文或完整工具输出。

用户反馈名称未改或要求补改时，只读取构建结果与本记录，再次尝试改名。复用原构建和验证结果，不重剪、不重建草稿。当前聊天标题是唯一修改目标；若截图实际指向其他项目名称，先核对对象。
